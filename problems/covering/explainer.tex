\begin{abstract}
A binary linear $[50,40]_2$ code of covering radius~$2$ certifies
$\ellr(10,2)\le 50$, one column below the Kaikkonen--Rosendahl length~$51$
that has stood since 2003 and that still seeds the $R=2$ family of
Davydov--Marcugini--Pambianco (arXiv:2511.02542). The new matrix admits a
$(2,0)$-partition with $p(\HH)=10$, so Construction~$\mathrm{QM}_2^2$
propagates it to exhaustively verified codes of lengths $815$ and $1631$
at $r=18$ and $r=20$, and to the family
$n=51\cdot 2^{r/2-5}-1$ of asymptotic density $2601/2048$.
This note explains the problem, how the matrix was found, what was proved,
and how to re-check every number from the committed text.
The matrices, verifiers, and \LaTeX\ source live at
\url{https://github.com/wustep/maths}.
\end{abstract}

\section{The problem}

\subsection{Covering radius}

Let $C\le\FF_2^n$ be a binary linear code of codimension $r$, so
$\lvert C\rvert=2^{n-r}$. Its \emph{covering radius} is the least $R$ such
that every vector of $\FF_2^n$ lies at Hamming distance at most $R$ from
some codeword. Equivalently, if $\HH$ is an $r\times n$ parity-check
matrix with column set $S\subset\FF_2^r$, every syndrome is a sum of at
most $R$ columns of $\HH$. Write $\ellr(r,R)$ for the least such length.

A binary linear code of length $n$ and dimension $k=n-r$ is written
$[n,k]_2$; when the covering radius is $R$ we append it, $[n,k]_2\,R$.
So a $[50,40]_2\,2$ code is binary of length $50$ and dimension $40$,
has covering radius $2$, and hence redundancy $r=10$.

For $R=2$ the condition is
\begin{equation}
\label{eq:cover}
\{0\}\cup S\cup(S+S)=\FF_2^r.
\end{equation}
A $(2,0)$-partition of the columns (Definition~3.2 of~\cite{DMP2025}) is a
partition into nonempty blocks such that every syndrome, including $0$, is
a sum of at most two columns from \emph{distinct} blocks. Write $p(\HH)$
for the number of blocks.

The finite covering density of an $[n,n-r]_2 2$ code is the exact rational
\[
\mu=\frac{1+n+\binom{n}{2}}{2^r}.
\]
Green's Problem~40 asks for the asymptotic density
\[
f(2)=\liminf_{r\to\infty}\mu\bigl(\ellr(r,2),r\bigr).
\]
For an infinite family of $[n(r),n(r)-r]_2\,2$ codes, write $\bar\mu(2)$
for the $\liminf$ of $\mu$ along the family as $r\to\infty$. Green's
$f(2)$ takes the $\liminf$ over the \emph{optimal} lengths $\ellr(r,2)$,
so any family bound $\bar\mu(2)\le c$ gives $f(2)\le c$.
It is not even known whether $f(2)=1$. The pre-2025 upper bound
$f(2)\le 729/512\approx 1.42383$ had stood since 1992. Davydov, Marcugini
and Pambianco~\cite{DMP2025} brought it to $2704/2048\approx 1.32031$ in
November 2025, by iterating a construction they call $\mathrm{QM}_2^2$
from a single seed. $\mathrm{QM}_2^2$ grows a short radius-$2$ covering
code into a longer one, provided the seed admits a $(2,0)$-partition into
few enough blocks; its exact input--output formula is recalled in
Section~\ref{sec:prop}.

\subsection{Why the $r=10$ cell is load-bearing}

Their Table~5.1, row $r=10$, still lists $n=51$: the
Kaikkonen--Rosendahl~\cite{KR2003} code of 2003, density
$1327/1024\approx 1.29590$. The entry is not bolded. Even the 2025 paper
did not improve it.

Their infinite family (Theorem~5.7) has lengths
\[
\Phi(r)=26\cdot 2^{r/2-4}-1=2^m(51+1)-1,\qquad m=r/2-5.
\]
The $52$ is the Kaikkonen--Rosendahl $51$, plus one. The whole family is
that one table cell pushed forward. Theorem~5.7(i) says the $2$-partitions
of $\HH_{KR}$ are ``very important for the next iterative process''.

So a $50$-column matrix at $r=10$ is not a one-cell footnote. If it admits
a small enough $(2,0)$-partition, it re-seeds the family. The paper's
computer search found $p(\HH_{KR})=11$.

\section{The process}

The searcher that found the matrix was run overnight on 16~August 2026
by an automated agent (Codex \texttt{gpt-5.6-sol}, Max). A committed,
deterministic reproduction of that run,
\path{compute/search_radius2.py}, encodes every constant quoted below;
none of this section is from memory.

\subsection{Encoding and seed}

Every matrix in this folder stores a column as an unsigned integer
whose bit $i$, counting from the least significant bit, is row $i+1$.
The ten identity columns are $1,2,4,\dots,512$.

The seed was the Kaikkonen--Rosendahl $51$-set: the ten identity
columns plus the $41$ hex words printed in Theorem~4.3
of~\cite{DMP2025}. The searcher reads those hex words directly as
LSB-first integers. The paper prints them MSB-first, so the matrix the
searcher actually holds is $\HH_{KR}$ with its rows in reverse order.
Row reversal is an invertible linear map on $\FF_2^{10}$, so the
reversed matrix is still a rank-$10$ covering matrix of radius $2$, and
no downstream claim depends on the orientation.

The $50$-subset was formed by trying all $51$ single deletions:
removing $\mathtt{0x1A3}=419$ leaves $11$ of the $1024$ syndromes
uncovered, and no deletion does better. The search therefore starts
eleven holes away from a witness.

\subsection{State, energy, and the incremental update}

The state is a set of exactly $50$ distinct nonzero ten-bit columns;
the cardinality never changes. An array of $1024$ counters records, for
every syndrome, how many of the $1+50+\binom{50}{2}=1276$
representations hit it: the empty sum, the $50$ singletons, and the
unordered pair-XORs. The energy is the number of counters at zero; a
witness is a state of energy $0$.

Swapping one column is cheap. Removing column $c$ decrements its own
counter and the $49$ counters $c\oplus c'$ for the columns $c'$ that
stay; inserting the replacement increments the same pattern. That is
about $100$ counter updates per proposal instead of a $1276$-term
recount, and a rejected proposal is undone the same way.

\subsection{Proposals, temperature, and restarts}

With probability $220/256$ a proposal aims at a hole: pick an uncovered
syndrome $g$ uniformly, then offer the column $g$ itself with
probability $1/64$, otherwise $g\oplus s$ for a uniformly chosen
current column $s$. The first offer covers $g$ as a new singleton; the
second covers it as a pair through $s$, unless the compensating
deletion happens to remove $s$. The searcher draws up to $100$ times
for an offer that is nonzero and not already a column; failing that,
and in the remaining $36/256$ of proposals, the offer is a uniform
random non-member. The column to delete is uniform among the $50$.

Acceptance is Metropolis on the change in energy: downhill and level
moves always pass, uphill moves pass with probability $e^{-\Delta/T}$.
The temperature runs in cycles of $80{,}000$ proposals; within a cycle,
$T=3.5\cdot 0.015^{\phi}$ as $\phi$ goes from $0$ to $1$, so each cycle
cools from $3.5$ to about $0.05$. At the end of a cycle the state
resets to the best configuration seen so far.

The random source is xorshift64 with shift constants $13$, $7$, $17$
and a fixed seed constant; that is run~$0$. Run~$0$ reached energy $0$
at proposal $3{,}600{,}281$, which is $281$ proposals after its $45$th
restart from best. The witness keeps $35$ of the $50$ starting columns;
the anneal replaced $15$.

Two replay commands. \texttt{python3 compute/search\_radius2.py}
re-checks the committed witness using the standard library alone.
\texttt{python3 compute/search\_radius2.py --search} replays discovery
run~$0$ deterministically; it needs NumPy and Numba.

\subsection{What the same search did not close}

The identical machinery failed on the prettier one-column gaps. At
$(r,n)=(8,25)$ the best anneal missed $3$ of $256$ syndromes; CP-SAT
returned \texttt{UNKNOWN} after $240$ seconds and Z3 after $180$. At
$(9,38)$, CP-SAT returned \texttt{UNKNOWN} after $300$ seconds, and
every single deletion from a reconstructed Gabidulin $39$-set missed at
least $8$ of $512$. At $n=49$, $r=10$, the anneal stalled at $7$ of
$1024$. All of these are search residues, not lower bounds.

Later sessions measured how deep the $n=49$ residue is
(\path{ATTACK.md}, 2026-08-18 and 19). Fresh deterministic anneals
stall at exactly $7$ holes again. The best $7$-hole configuration
admits no swap of five or fewer columns reaching zero holes, an
exhaustive claim over all $\binom{49}{5}=1{,}906{,}884$ removal sets
with an exact re-add search, validated on four out of four planted
controls. A second $7$-hole optimum admits no swap of four or fewer
columns, and a color-guided backtracking search proves that no linear
map of
$\FF_2^{10}$ carries one $49$-set to the other, so the landscape has at
least two distinct deep basins at $7$ holes. Separately, $79$ subgroup
classes of $GL(10,2)$ were exhausted with zero invariant
$49$-coverings. None of this bounds $\ellr(10,2)$ from below; it says
the known near-misses are far from any witness. Replay:
\texttt{python3 compute/q4/verify\_config.py
compute/q4/best\_sa\_config.cols} prints the seven holes, and the
exhaustion logs are \path{compute/q4/kswap5_sa.log} and
\path{compute/q4/orbit_runs.log}.

\subsection{Where the partition came from}

The overnight run stopped at the table cell; it never computed a
partition. The $10$-block $(2,0)$-partition was produced the same day
in an intermediate session, and it entered the repository as an
unverified claim: the brief handed to the verification session listed
the ten blocks and instructed that session to check them from scratch
and stop if any check failed. The intermediate session's scripts were
deleted under a quarantine protocol once verification passed, so that
the two checkers would remain the only implementations in the tree.
The code that first found the partition is therefore not preserved.
What is committed is the partition itself,
\path{result/data/partition_p10.json}, consulted for block labels only,
and two independent checkers that re-derive the columns from the matrix
text and sweep all $1024$ syndromes.

The certified pair statistics show what any such search is up against.
Of the $973$ syndromes that need a pair, $821$ have a unique one, and
each unique pair forces its two columns into distinct blocks. Those
constraints form a graph on the $50$ columns with $821$ edges, and a
valid $(2,0)$-partition is a proper coloring of that graph which, for
each of the remaining $152$ syndromes, also splits at least one of its
$2$ to $6$ pairs across blocks. So most of the partition is forced
before any search begins, and checking a candidate costs one pass over
the $1276$ sums. No claim is made that $10$ blocks is the minimum.

Ten blocks is what the propagation needs, and less than what was
published. Construction $\mathrm{QM}_2^2$ requires
$p(\HH_0)\le 2^m\le n_0$, so $p=10$ keeps both $m=4$ and $m=5$ legal
with room to spare, and it beats the computer-searched
$p(\HH_{KR})=11$ of~\cite{DMP2025} on a matrix one column shorter.

\subsection{From search output to artifact}

The overnight folder never ran $\mathrm{QM}_2^2$ and still quoted the
stale $f(2)\le 1.4238$.

A later session (Claude, afternoon of the same day) treated everything
upstream as a claim to be verified, not as a trusted input:
reconstructed the Kaikkonen--Rosendahl baseline from the hex in
Theorem~4.3 of~\cite{DMP2025}, checked the $50$-set and the partition,
implemented $\mathrm{QM}_2^2$ from equations (4.2) and (4.4), and
exhaustively checked the $r=18$ and $r=20$ outputs. Two verifiers were
written from scratch in two languages, then a third quarantined oracle
was run once as a post-hoc diff. The search procedure is not part of
the argument. The argument is a finite decidable statement about
committed matrices, re-checkable in seconds.

\subsection{Minimality}

Deleting any one of the $50$ columns leaves at least $9$ syndromes
uncovered. The best deletions, columns $381$, $479$ and $927$, leave
exactly $9$. So the $50$-set is a minimal $1$-saturating set in $PG(9,2)$,
equivalently a locally optimal (LO) covering code (the geometric name for
a covering-radius-$2$ column set with no redundant column). It is not
padded.

\subsection{Propagation}
\label{sec:prop}

Construction $\mathrm{QM}_2^2$ (\cite{DMP2025}, Theorem~4.1) takes an
$[n_0,n_0-r_0]_2 2$ code with a $2$-partition into $p(\HH_0)$ blocks, an
indicator set $\mathscr{B}=\FF_{2^m}$ subject to
$n_0\ge 2^m\ge p(\HH_0)$, and $\boldsymbol{D}=\boldsymbol{D}_1(2)$, and returns
\[
n=2^m(n_0+1)-1,\qquad r=r_0+2m,\qquad p(\HH_C)\le 2^{m+1}+1.
\]
With $n_0=50$ and $p(\HH_0)=10$ the inequality permits exactly $m=4$ and
$m=5$ ($2^6=64>50$). Both outputs were enumerated completely:

\subsection{The family}

Iterating from $(r,p)=(10,10)$ with the paper's bound
$p(\HH_C)\le 2^{m+1}+1$, the even $r\le 64$ reachable by
$\mathrm{QM}_2^2$ are
\[
10,18,20,30,32,34,36,38,40,46,48,50,52,54,56,58,60,62,64.
\]
The even $r$ \emph{not} reachable this way are
$12,14,16,22,24,26,28,42,44$. Those gaps are real. The paper fills its
own $r=22,24,26$ with $\mathrm{QM}_3^2$ and $r=28$ with
$\mathrm{QM}_5^2$; the analogues are not implemented here.

Closed form on the reachable even $r$:
\[
n=51\cdot 2^{r/2-5}-1,\qquad
\mu=\frac{51^2}{2^{11}}-\frac{51}{2^{r/2+1}}+\frac{1}{2^r}
\ \nearrow\ \frac{2601}{2048}\approx 1.27002.
\]
Hence $\bar\mu(2)\le 2601/2048$, and since $f(2)$ is a $\liminf$ over $r$,
also $f(2)\le 2601/2048$. Against the literature:

\subsection{How to re-run}

The code is the public repository
\url{https://github.com/wustep/maths}.
Clone it, then run the pipeline from the covering-result directory:

\begin{verbatim}
git clone https://github.com/wustep/maths.git
cd maths/problems/covering/result
./run_all.sh
\end{verbatim}
Needs \texttt{python3} and \texttt{rustc}. After the clone, no network,
no packages, no RNG. Seventy-four named assertions, exit~$0$, output
byte-identical across runs (about two seconds). Direct links:
\url{https://github.com/wustep/maths/tree/main/problems/covering/result}
and
\href{https://github.com/wustep/maths/blob/main/problems/covering/result/run_all.sh}{\texttt{result/run\_all.sh}}.

\subsection{Two verifiers, opposite algorithms}

\path{verify/verify.py} is pair-driven: walk all $\binom{n}{2}$ pairs,
mark the syndromes they hit, then sweep $2^r$ for anything unmarked.
\path{verify/verify.rs} is syndrome-driven: for each of the $2^r$
syndromes, scan the columns and test membership of $s\oplus h$. It then
runs its own pair loop and refuses to report unless the two verdicts
agree. They also differ in parser, rank pivot (lowest vs highest set
bit), and exact rational arithmetic. \path{run_all.sh} diffs their
fact dumps.

Both read the matrix from \emph{text}. Neither consults a stored
certificate. The partition JSON is used only for block labels; the
columns themselves are re-derived from the matrix.

\subsection{Encoding}

Everything in the repo is LSB-first: bit $i$ of a column integer is
row $i+1$. The hex listing of $M_{KR}$ in~\cite{DMP2025} Theorem~4.3 is
the opposite (MSB-first, row~$1$ as the high bit). Reconstructing
$\HH_{KR}=[I_{10}\mid M_{KR}]$ reverses the ten bits. A from-scratch
verifier that misses the reversal fails on the Kaikkonen--Rosendahl
baseline \emph{and only there}, which is a useful signal. The reversal
is pinned by the paper's own Theorem~5.2(ii),
$h_5+h_{27}+h_{29}=0$, asserted in the builder as a canary.

A reader using the opposite convention gets the bit-reverse of every
column, an $\FF_2$-linear relabelling of $\FF_2^{10}$, and every claim
here is preserved.

\subsection{Independence, honestly}

Both verifiers were written in one session by one author. Two languages,
two algorithms, two parsers, no shared code, but not two people. A
third, quarantined oracle was run once after both were green and agreed
everywhere; it is not in the tree.

\section{What is not claimed}

\begin{itemize}
\item $50$ is not shown optimal. Sphere-covering gives only
$\ellr(10,2)\ge 45$, since $1+n+\binom{n}{2}\ge 1024$ fails at $n=44$,
which gives only $991$.
Minimality says this particular $50$-set has no redundant column, which
says nothing about a different $49$-set.
\item The $n=49$ runs leaving $7$ uncovered syndromes are search
residue, not a lower bound. The residue is deep (no $\le 5$-column swap
fixes the best near-miss, and there are two inequivalent near-misses;
see Section~2.4), but depth of a residue is still not a bound.
\item The gaps $(8,25)$ and $(9,38)$ remain open.
\item Only $m=4$ and $m=5$ are exhaustively verified. The rest of the
family inherits $p(\HH_C)\le 2^{m+1}+1$ from~\cite{DMP2025}~(4.4).
\item Within \path{result/}, nothing is claimed for
$r\in\{12,14,16,22,24,26,28,42,44\}$. Later work recorded in
\path{ATTACK.md} implemented $\mathrm{QM}_3^2$ and $\mathrm{QM}_5^2$
from this seed and certified $r=22,24,26,28$
(Section~\ref{sec:later}); $r=12,14,16$ still carry no claim from this
seed.
\item $f(2)\le 2601/2048$ is an upper bound only. Whether $f(2)=1$ is
untouched.
\item Priority is unresolved. Table~5.1 of~\cite{DMP2025} is ``best as
far as the authors know''. A $\ellr(10,2)\le 50$ may already exist in
ACCT proceedings. See
\href{https://github.com/wustep/maths/blob/main/problems/covering/result/PRIORITY.md}{\texttt{result/PRIORITY.md}}
in the repository.
\end{itemize}
