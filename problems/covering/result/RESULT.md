# Result summary

$\ell_2(10,2) \le 50$, with the $r=10$ seed propagated through Construction
QM$_2^2$ to a new $R=2$ family of asymptotic covering density $2601/2048$.

The mathematics is in [`NOTE.md`](NOTE.md). This file is the operational
summary: what is here, how to run it, and what happened when it ran.

## Run it

```bash
cd problems/covering/result
./run_all.sh          # or: make
```

Needs `python3` and `rustc`, nothing else. No network, no packages, no RNG,
under two seconds. Exit 0 means every claim below re-derived from the committed
matrix text.

**Status: 74 checks passed, exit 0.** Output is byte-identical across runs
(confirmed by running twice and `cmp`).

## Numbers that disagreed with the brief

The instructions said the code wins. One number lost.

- **Asymptotic density decimal.** The brief gave
  $51^2/2^{11} = 2601/2048 \approx 1.26999$. The fraction is right; the decimal
  is not. $2601/2048 = 1.27001953125$, so $\approx 1.27002$. Used throughout as
  1.27002. This is a rounding slip in the brief, not a mathematical
  disagreement, and it does not affect any bound: the finite densities approach
  $2601/2048$ from below, so $f(2) \le 2601/2048$ stands either way.

Everything else in the brief matched exactly: all four histograms, 973, 821, the
minimality figure of 9, the 10 dependent triples, $(491,734,821)$ in blocks
6/4/9, both propagated lengths, both propagated densities, and the legal-$m$ set
$\{4,5\}$.

## Reference kit comparison

`../_reference/` was a scaffold from a previous agent session. Its
`scripts/oracle_check.py` was quarantined until both verifiers here were written
and `run_all.sh` was green; it was then run once as a post-hoc diff. No oracle
code was copied.

- **KR baseline: identical.** `data/kr_r10_n51.txt` and the kit's reconstruction
  agree byte for byte. Since that file is the one place the MSB-first paper
  convention meets the LSB-first repo convention, two independent reconstructions
  landing on the same 51 columns is a real confirmation of the bit order.
- **$r=18$ and $r=20$: different, and both verify.** The indicator allocation in
  Construction QM is a free choice (any assignment giving distinct blocks
  distinct indicators and exhausting $\mathbb F_{2^m}$ works), so different
  allocators give different matrices. Of the 815 columns at $r=18$, 720 are not
  in the kit's matrix at all; at $r=20$, 1457 of 1631. Both matrices pass the
  full exhaustive check, and both have $\mathbb F_2$-rank $r$ and density
  $332521/262144$ and $1330897/1048576$ respectively. So these are **two
  distinct verifying witnesses** at each of $r=18$ and $r=20$, which is stronger
  than agreement would have been.
- **Oracle values: agree everywhere.** `oracle_check.py` reports exactly the
  same shape, rank, coverage, density, histograms, forced-split count,
  minimality figure, triple count and $p(H)$ as both verifiers here. Three
  implementations, three algorithms, no shared code.

`_reference/scripts/` and the kit tarball are deleted from this branch;
`_reference/README.md`, `_reference/CLAUDE_PROMPT.md` and `_reference/data/` are
kept for provenance, with a note appended to the kit README saying so.

## What is not done

Named plainly, because these are the things a referee will ask about:

1. **Partitions past $m=5$ are inherited, not computed.** $r=18$ and $r=20$ are
   exhaustively verified. The rest of the family rests on the paper's
   $p(H_C) \le 2^{m+1}+1$ from (4.4). Computing those partitions explicitly is
   the single highest-value follow-up.
2. **QM$_3^2$ and QM$_5^2$ are not implemented**, so $r \in \{12,14,16,22,24,26,28,42,44\}$
   get no claim from this seed even though §5 of `NOTE.md` supplies the
   dependent triple that QM$_5^2$ needs at $r=28$.
3. **No lower bound work.** $\ell_2(10,2) \ge 45$ is just sphere-covering.
4. **Priority is unresolved.** See [`PRIORITY.md`](PRIORITY.md). Nothing should
   be posted until a human has done those checks and heard back from Davydov,
   Marcugini and Pambianco.
